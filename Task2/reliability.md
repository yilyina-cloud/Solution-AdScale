Надёжность RTB
Circuit Breaker

Для синхронных вызовов RTB используется Circuit Breaker.

Если зависимый сервис недоступен или регулярно превышает timeout, новые вызовы временно прекращаются.

Это предотвращает накопление запросов и каскадные сбои.

Retry

Повторные попытки используются только для безопасных и идемпотентных операций.

Для RTB количество retry минимально, так как общий latency ограничен 80 ms.

Для асинхронной обработки событий допускаются повторные попытки с exponential backoff.

После исчерпания попыток событие может быть отправлено в DLQ.

Timeout

Каждый синхронный вызов внутри RTB имеет короткий timeout и собственный latency budget.

Зависший сервис не должен блокировать весь аукцион.

Fallback

Если необходимые данные временно недоступны, используются:

Последние доступные данные из RTB Cache.
Дефолтное правило ставки, если оно допустимо.
NO_BID, если безопасный расчёт выполнить невозможно.

Для RTB лучше быстро вернуть NO_BID, чем нарушить SLA.

Идемпотентность финансовых операций

Для платежей, списаний и пополнений используется idempotency key.

Повтор одного и того же запроса не должен приводить к повторному списанию или пополнению.

Изоляция некритичных компонентов

Сбой Statistics или Analytics не должен останавливать RTB.

Impressions и clicks передаются через Kafka и обрабатываются независимо от аукциона.

Мониторинг

Контролируются:

P95/P99 latency;
timeout rate;
error rate;
состояние Circuit Breaker;
количество retry;
consumer lag Kafka;
размер DLQ.
