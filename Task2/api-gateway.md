API Gateway для DSP
Назначение

Для интеграции с DSP используется отдельный RTB Gateway.

Он находится перед RTB-сервисами и отвечает за внешний API, но не содержит бизнес-логику аукциона.

Основные функции

RTB Gateway выполняет:

Приём bid requests по HTTPS / OpenRTB.
Аутентификацию DSP.
Валидацию входящих запросов.
Rate limiting.
Маршрутизацию в RTB-сервисы.
Применение timeout.
Circuit Breaker для зависимых сервисов.
Сбор метрик latency и ошибок.
Маршрутизация
DSP
 ↓
Load Balancer
 ↓
RTB Gateway
 ↓
Ad Selection Service
 ↓
Bidding Service
 ↓
Delivery Service

Для каждого DSP используется отдельная конфигурация адаптера, но внутренняя модель запроса остаётся единой.

Rate limiting

Ограничение частоты запросов применяется на уровне DSP-партнёра.

Это защищает RTB-контур от резких всплесков нагрузки и ошибочного трафика.

При превышении лимита запрос отклоняется без передачи в Bidding Service.

Аутентификация

DSP аутентифицируется на RTB Gateway.

Возможные варианты:

API key;
mTLS;
подписанные запросы.

Конкретный механизм зависит от контракта с DSP.

Circuit Breaker

Если зависимый RTB-сервис временно недоступен или превышает timeout, Circuit Breaker прекращает новые вызовы на короткий период.

Это предотвращает накопление зависших запросов и каскадные сбои.

Мониторинг

Для Gateway отслеживаются:

RPS;
P95/P99 latency;
количество ошибок;
timeout;
rate limit rejects;
состояние Circuit Breaker.

Основная цель — не допустить превышения SLA и быстро выявлять деградацию RTB-потока.
